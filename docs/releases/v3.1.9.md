# Universal Extractor 2 v3.1.9

This release fixes file/libmagic detection for Unicode input filenames and
Unicode installation folders, including Japanese paths unsupported by the
helpers' Windows ANSI code page.

## Changes

- Let Windows open the input and pass a seekable file handle to the detector.
  Load magic.mgc relative to the helper directory. No archive copy, rename,
  temporary hard link or short filename is needed.
- Preserve literal percent signs, exclamation marks, ampersands, carets and
  parentheses in detector paths.
- Require successful command completion before accepting a detector result.
  Missing inputs, launch errors and incomplete output remain unknown and use
  the existing fallback to the legacy helper.
- Test the production detection functions against both bundled helpers with
  Unicode input and installation paths, real ZIP/text/PE/PDF files and failure
  cases. Verify that input files and existing environment values are preserved.

The pinned detector binaries, databases, source packages and license notices
from v3.1.8 are unchanged. The normal and optional external FreeArc paths retain
their regression coverage. Bio.cs remains at the validated release version;
its separate upgrade candidate is not included.

This fix concerns file/libmagic detection. Other extraction helpers retain
their existing Unicode handling. See [implementation and tests](../LIBMAGIC-UNICODE.md).

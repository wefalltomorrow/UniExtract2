# Universal Extractor 2 v3.1.8

This release updates the preferred file-type detector on 64-bit Windows to
file/libmagic 5.48 and improves fallback when a detector cannot identify a file.

## Changes

- Use the verified 64-bit file/libmagic 5.48 helper and matching magic database.
  Keep the existing 32-bit helper for 32-bit Windows and unsuccessful detection.
- Request brief detector output and normalize both brief and filename-prefixed
  results. Reject unknown data, missing databases, launch failures and error
  messages before deciding whether to try the legacy helper.
- Pin five official MSYS2 binary packages and seven runtime/database hashes.
  Include the matching source packages, patches, build recipes, inventories
  and license notices. No global MSYS2 installation is required.
- Check runtime dependencies in an isolated environment and verify detector
  fallback with production AutoIt regression tests. Packaged checks exercise
  the updated helper alongside existing extraction and FreeArc coverage.
- Retain the optional FreeArc backend and corrected status reports from v3.1.7.

## Known limitation

On the validation machine, both the new and legacy helpers failed to open a
Japanese input path under the active Windows code page. UniExtract rejects
that error as an identification and continues through other detection routes.
Unicode ZIP extraction is covered separately; this does not imply that the
helper itself recognizes every Unicode path.

[source and rebuild information](../LIBMAGIC-SOURCES.md).
